Reverse engineering Android : les bases pour auditer une application

Ce qu'il faut comprendre avant de faire auditer (ou d'auditer soi-même) la sécurité d'une application mobile Android.

Avant de publier une application Android, la plupart des équipes testent son bon fonctionnement — mais peu vérifient réellement ce qu'un attaquant peut en extraire une fois le fichier APK entre ses mains. C'est là qu'intervient le reverse engineering : la capacité à décompiler et analyser une application pour comprendre son comportement interne.

Pourquoi une application Android n'est jamais "vraiment" cachée

Contrairement à une idée reçue, le code d'une application Android n'est pas totalement protégé une fois installée sur un téléphone. Des outils comme les décompilateurs permettent de remonter jusqu'à une version lisible du code source, ou en tout cas suffisamment proche pour en comprendre la logique métier.

Cela signifie concrètement que : les clés d'API codées en dur, la logique de validation des paiements, ou les règles de sécurité internes peuvent être exposées si elles ne sont pas correctement protégées côté serveur.

Les points qu'un audit vérifie en priorité

  • Stockage des secrets : clés API, tokens, identifiants codés en dur dans l'application.
  • Communication réseau : les échanges sont-ils correctement chiffrés (certificate pinning, HTTPS strict) ?
  • Logique métier côté client : les règles critiques (prix, permissions, validations) sont-elles vérifiables/modifiables localement ?
  • Protections anti-tampering : l'application détecte-t-elle si elle tourne sur un appareil "rooté" ou modifié ?
  • Obfuscation du code : le code est-il rendu suffisamment difficile à lire pour ralentir un attaquant ?
À retenir : le reverse engineering n'est pas réservé aux attaquants. C'est avant tout un outil défensif : la meilleure façon de savoir ce qu'un attaquant pourrait trouver, c'est de le chercher soi-même en premier.

Ce que ça change concrètement pour une entreprise

Une application non auditée qui gère des paiements, des données utilisateurs ou des accès sensibles représente un risque direct : fuite de données, fraude, ou atteinte à la réputation en cas d'incident public. Un audit structuré permet d'identifier ces failles avant qu'un tiers malveillant ne les trouve.
